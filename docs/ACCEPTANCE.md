# Framework v1.1 Acceptance Evidence

## Implemented capabilities

Core administration uses strict manifests, explicit A/B/C/D ownership and
descriptor-relative file inspection. Existing registered installations support
zero-write plans, conservative B/L/N merging, conflict/stale-plan rejection,
verified backups, durable per-file journals, interruption recovery and guarded
rollback. Unknown/scientific files, local instructions and independent histories
are outside the managed mutation set.

One source package and starter generate a self-contained zip application and
versioned archive. Fresh creation uses no-clobber staging. Metadata-free observed
v0.5 adoption has its own conservative plan and external backup/journal, including
recovery before installation metadata exists. No reporting or scientific
reorganization occurs during administration.

Scientific commands implement researcher-adopted Research Map revisions,
epistemic Narrative categories, flexible many-to-many Workstream/Aim associations,
AST/Specifications, stable non-recycled IDs, optional Runs and independent
manuscript claims/evidence/contradictions/limitations. Interrupted registration
resumes the same ID. Approvals are recorded attestations, never fabricated
authentication. Program discussion requires no unit and completion starts no work.

Reporting implements eleven paired sections, detailed applicable Methods, exact
metadata/scalar/math correspondence checks, six editable/rendered outputs,
table-only evidence, explicit font/glyph/asset/math failure, intended physical
figure sizing and revision preservation. No arbitrary report length restriction
exists. Provenance, execution validation and cross-agent handoffs retain known
and missing evidence. HPC helpers prepare human-operated commands and inspect
launchers without remote access or scientific environment provisioning.

## Automated evidence

The synthetic suite covers malformed manifests/state, unsafe paths/types,
symlink/hardlink/case/parent changes, ownership persistence, local changes/deletions,
merge conflicts, stale plans, backup/stage/journal corruption, interrupted writes,
rollback chains and later edits. New suites cover archive-only initialization,
legacy adoption and guarded undo, CLI updates/rollback, five modality-independent
record-creation scenarios, approval/ID/revision boundaries, Runs/handoffs/HPC,
report structures and optional real-renderer negative/failure cases. JSON schemas
are generated from maintained definitions; semantic Python validators remain
authoritative for filesystem and scientific relationship checks.

At the pre-final checkpoint, 152 tests ran: 141 passed and 11 were explicitly
skipped (optional renderer environment plus one sandbox-restricted real socket
creation). Socket-type rejection is separately exercised without creating one.
The separately selected reporting environment passed all 15 then-current report
tests, including real EN/KO rendering, math, PNG/PDF/SVG export, missing fonts,
interrupted publication and later-edit guards. Additional negative rendering
cases and final regression results are recorded at release acceptance below.

Archive-only tests launch the generated zip application from a temporary working
directory without development PYTHONPATH. They create fresh projects, five
scientific modality records, migrate a synthetic v0.5 tree preserving local
reporting code and scientific records, merge an update and exercise guarded
rollback. Public audits inspect embedded/base64 runtime assets and unpublished
Git blobs, not only the latest working tree. Tar ownership/timestamps are normalized.

## Rendering and manual review

The observed reporting environment uses Python 3.11, Pandoc 2.12, WeasyPrint 66.0,
Matplotlib 3.11.2, Pillow 13 and fontTools 4.68. External actual Noto Serif,
Noto Serif KR and Arial font files were used; no fonts enter framework artifacts.
A synthetic table, defined mean equation and four-point plot were rendered in
both languages with long Methods and no page-count gate. Rasterized PDF pages
were visually inspected for text/glyphs, math, tables, captions and page flow.
The first visual review found that intrinsic PNG sizing enlarged an 85 mm figure;
the renderer now applies declared physical width explicitly. Final review must
use the corrected candidate. The variable-font renderer emits an upstream
fontTools deprecation warning; no missing glyph or failed output was observed.

The Windows computer-use adapter could not initialize because its sandbox path
was not accepted as a local file URI. No Windows automation was performed. Linux
headless-browser inspection is used independently; no research environment is
changed to work around the adapter.

## Practical limits and unperformed work

- Administration is tested on Linux/WSL with ordinary current-user/group files,
  one filesystem and sufficient no-atime rights. Unsupported ACLs/xattrs,
  hardlinks, cross-filesystem paths and ambiguous ancestors fail closed.
- Advisory locks require cooperating writers. Quiesce administrative targets
  during apply; no protection against a same-user adversary rewriting all trusted
  state or a noncooperating writer in a final syscall race is claimed.
- MathText supports a TeX subset. Scalar/structural checks do not certify
  methodological adequacy, statistics, bilingual meaning, every journal layout,
  remote cluster policy or every agent vendor's instruction-loading behavior.
- No real wet-lab/regulated activity, external HPC job or scientific rerun was
  performed. Synthetic acceptance does not pretend otherwise. Humans retain
  scientific decisions, primary-system permissions and actual execution.
- No license grant has been established. Fonts/dependencies remain external;
  publication does not invent redistribution rights.
- An active target is not considered migrated until its final exact plan,
  recoverable backups, conflict resolution and integrity checks are verified.

## Final release checkpoint

The renderer-enabled complete suite ran 155 tests: 154 passed; actual Unix socket
creation was skipped because this sandbox rejects it. Independent socket-type
rejection still passed. The core-only environment passed 141 with 14 explicit
optional/sandbox skips. GitHub verified both Python 3.9 and 3.11 successfully on
the committed implementation candidate. No hidden renderer skip is called a pass.

A clean source commit generated the independently usable 1.1.0-rc.1 candidate.
Source/unpublished-history audits and the 58-entry archive audit found no private
context/credential patterns or unsafe ownership headers. No protected content
was copied into the public candidate. These audits supplement manual source review.

The corrected candidate was used to create a fresh synthetic project and render
EN/KO reports through its installed zip runtime. Both PDF outputs had three pages
(informational). All six rasterized PDF pages and full HTML screenshots were
visually inspected: text/glyphs, equation notation, tables, captions, Figure and
page flow were present without observed clipping. Linux Chromium inspection
confirmed eleven headings per language, loaded report fonts, complete images,
no horizontal overflow, no page errors and an 85 mm Figure displayed at 321.25
CSS pixels. All external browser requests were blocked. The browser and its
temporary profile were isolated under temporary storage; no research environment
or Windows configuration was changed.
