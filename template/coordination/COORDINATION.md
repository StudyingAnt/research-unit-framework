# Coordination

Start with a discussion: “Start Coordination. Read the Research Map and relevant
plans; help me examine the current questions, evidence and priorities.”

1. Read `plans/RESEARCH_MAP.md` and the relevant Aim/Strategy records. An empty
   map is a valid starting point; do not invent a research program to fill it.
2. Discover `reports/A###-S##-T##/` from the project root as needed. Read the
   current scientific sources and relevant revisions, figures and provenance;
   completed execution is not proof that a hypothesis is supported.
3. Critically discuss hypotheses, alternatives, controls, missing evidence,
   uncertainty, dependencies and the cost or feasibility of candidate work.
   Distinguish observation, inference, alternative and synthesis.
4. Propose Narrative, Workstream, Aim, priority or manuscript changes. Workstreams
   are flexible scientific purposes, not a compulsory technology taxonomy.
5. Adopt only the decisions the researcher explicitly accepts. Update the
   appropriate map, Aim or manuscript record with date, approval reference,
   rationale, affected links and remaining uncertainties. Leave other ideas in
   discussion or clearly marked notes. Do not treat every idea as a formal record.

Coordination can integrate evidence across AST reports into multiple manuscript
arguments, including contradictory findings. Researchers select claims and
publication structure. A manuscript is not the parent of AST identity.

An AST session reads relevant plans, performs its approved task and maintains its
own report and figures. Later Coordination sessions read those files when useful.
There is no required cross-session message, summary file or automatic handoff.
Repeated reporting revisions retain the same AST unless the evidence-producing
question has substantively changed. Interrupted work resumes its existing ID.
